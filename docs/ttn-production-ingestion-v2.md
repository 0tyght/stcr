# TTN Production Ingestion V2

ไฟล์ Production สำหรับ Import:

`output/node-red/ttn-production-ingestion-v2-production.json`

## สิ่งที่แก้

- รองรับเตา TTN 1-9 ครบทุกเตา
- อ่าน Modbus ตามลำดับ `สถานะ -> เลขรอบ -> อุณหภูมิเตา/Blower -> ความชื้น/ห้องอบ`
- เหลื่อมเวลาอ่านแต่ละ PLC 20 วินาที จึงไม่ยิงคำสั่งพร้อมกันทั้งหมด
- ใช้ Modbus client แยกสำหรับ V2 โดยตั้ง Command Delay 50 ms และ Client Timeout 3000 ms
- หากอ่านไม่ทัน ระบบรอ 1.5 วินาทีและ Retry อัตโนมัติสูงสุด 2 ครั้ง
- ไม่ใช้ Delay และ Join ในเส้นทางรับข้อมูล
- ส่งสถานะเปิดหรือปิดทุกนาที แม้เตาปิดอยู่
- ส่งเซนเซอร์ทุกนาทีทั้งตอนเปิดและปิด เพื่อยืนยันว่า PLC ยังเชื่อมต่อ
- ไม่ส่ง payload ที่มี `null`; ถ้าอ่านไม่ครบจะบันทึก Error และรออ่านใหม่ในรอบถัดไป
- ใช้ค่า Blower จริงของเตา 1
- แจ้งเตือนรายชั่วโมงด้วย Cron ตรงต้นชั่วโมง ไม่ใช้ Timer ทุก 60 วินาที
- สรุป LINE ทำงานนาทีที่ 1 ของทุกชั่วโมง หลังรอบอ่านทั้ง 9 เตาเสร็จ
- หากข้อมูลยังไม่ครบ ระบบตรวจซ้ำทุก 10 วินาที สูงสุด 6 ครั้ง และไม่ส่งรายงานที่ข้อมูลขาด

## วิธีสลับ Flow อย่างปลอดภัย

1. สำรอง Flow เดิมจาก Node-RED ก่อน
2. ถ้ามี V2 รุ่นก่อนอยู่ ให้ Delete Tab รุ่นก่อน แต่ยังไม่ต้อง Deploy
3. Import ไฟล์ Production เป็น New Flow; Tab ที่ Import จะถูกปิดไว้โดยตั้งใจ
4. เปิด Tab Production ใหม่
5. ปิด Inject เดิมที่ตั้ง `repeat: 60` ใน Tab `notify`
6. ปิด Tab `DB` เดิม
7. ตรวจว่า Bridge ใน `notify` ยังต่อเข้าชุด LINE เดิม
8. Deploy แบบ Full เพียงครั้งเดียว
9. ตรวจ Debug, `/stcr/api/health` และหน้าเว็บว่าเตา 1-9 อัปเดตทุกนาที

## ข้อควรระวัง

- Flow นี้อ้างอิง Modbus client และ MQTT broker เดิมจากเครื่องโรงงาน จึงต้อง Import ใน Node-RED เครื่องเดิม
- ใช้ Unit ID ตาม PLC จริง: 183, 184 และ 185
- รูปแบบเวลายังคงเข้ากันกับ Backend ปัจจุบันซึ่งตั้ง source offset ไว้ 420 นาที
- Flow ใหม่เรียก Function ส่ง LINE เดิม จึงใช้ Token และกลุ่มเดิมโดยไม่คัดลอกรหัสลับเพิ่ม
- Token LINE ที่ฝังอยู่ใน Flow เดิมถือว่าเปิดเผยแล้ว หลังระบบนิ่งควรออก Token ใหม่และย้ายไปเก็บผ่าน Environment
- อย่าเปิด Flow DB เดิมและ V2 พร้อมกัน
