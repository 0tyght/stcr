# Node-RED V9: รายงานรายชั่วโมงที่รอข้อมูลครบ

ไฟล์พร้อมนำเข้า:

- `output/node-red/gr-production-complete-v9.json`
- `output/node-red/ttn-production-complete-v9.json`

## สิ่งที่แก้

- รายงานไม่อ่าน Modbus ทุกเตาพร้อมกันตอนต้นชั่วโมงอีกต่อไป แต่ใช้ค่าล่าสุดจากรอบอ่านปกติที่กระจายเวลาไว้แล้ว
- ตรวจข้อมูลทุก 1 นาที และรอข้อมูลที่แต่ละเตาควรมีจริงให้ครบ โดยยอมรับข้อมูลที่มีอายุไม่เกิน 5 นาที
- GR เตา 11–17 รอเฉพาะอุณหภูมิห้องอบและความชื้น
- GR เตา 18 รออุณหภูมิเตา อุณหภูมิห้องอบ และความชื้น โดยไม่รอ Blower
- GR เตา 19–26 รออุณหภูมิเตา Blower อุณหภูมิห้องอบ และความชื้น
- TTN เตา 1–9 รอข้อมูลเซนเซอร์ครบตามรูปแบบเดิม
- แสดงเฉพาะเตาที่เปิดอยู่ในข้อความรายชั่วโมง
- ไม่แทนค่าที่หายด้วยเลขศูนย์ และไม่ส่งรายงานที่ข้อมูลไม่ครบ
- นับว่าส่งสำเร็จเมื่อ LINE ตอบกลับ HTTP 2xx เท่านั้น ถ้าส่งไม่สำเร็จจะเก็บข้อความค้างและลองใหม่
- ปิดตัวตั้งเวลารายงานแบบเก่าในไฟล์ V9 แล้ว เพื่อไม่ให้ยิงอ่าน Modbus ซ้ำหรือส่งข้อความซ้ำ

## วิธีนำเข้า

1. สำรอง Flow ปัจจุบันด้วย Export ก่อน
2. ปิดการทำงานของแท็บชุดเดิมทั้งบริษัท แล้วกด Deploy
3. Import ไฟล์ V9 ของบริษัทนั้นเป็น Flow ทั้งชุด
4. ตรวจว่ามีเพียงชุด V9 ที่ Enabled แล้วกด Deploy
5. รอให้ค่าล่าสุดครบและกด Inject `ทดสอบรายงานด้วยค่าล่าสุด`
6. ดู Debug `ผลรายงานรายชั่วโมง V9` ต้องขึ้น `ok: true`

อย่าเปิด Flow เดิมและ V9 พร้อมกัน เพราะจะอ่าน PLC/MQTT และส่ง LINE ซ้ำกัน
