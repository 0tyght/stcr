# STCR TTN Production Flow V3

ไฟล์สำหรับ Import:

`output/node-red/ttn-production-complete-v3.json`

## สิ่งที่รวมอยู่ในชุดใหม่

- อ่านข้อมูลจริงครบ 9 เตา: สถานะทำงาน สถานะอุ่นเตา เลขรอบ อุณหภูมิเตา
  อุณหภูมิ Blower ความชื้น และอุณหภูมิห้องอบ
- อ่านแรงดันไฟฟ้า AB, BC และ CA
- ส่ง Topic `test` และ `sensor` เมื่อข้อมูลของเตานั้นครบทั้งชุดเท่านั้น
- แจ้งเริ่ม/หยุดทำงาน และเริ่ม/หยุดอุ่นเตาครบ 9 เตา
- แจ้งอุณหภูมิห้องอบเกิน 65°C
- แจ้งอุณหภูมิเตาเผาต่ำ/สูง ขณะเตาทำงาน
- แจ้งไฟต่ำกว่า 360 V หรือสูงกว่า 425 V และแจ้งเมื่อค่ากลับมาปกติ
- Retry จุดอ่าน Modbus ที่ Timeout สูงสุด 2 ครั้ง
- แจ้ง Modbus ขาดการเชื่อมต่อ โดยจำกัดข้อความซ้ำจุดเดิมทุก 15 นาที
- สรุปรายชั่วโมงเมื่อข้อมูล 9 เตาและแรงดัน 3 เฟสสดใหม่ครบ

## วิธีเปลี่ยน Flow โดยไม่ให้ข้อมูลซ้ำ

1. Export `All flows` เก็บเป็นไฟล์สำรองก่อน
2. Import `ttn-production-complete-v3.json` แบบ `New Flow`
3. ยังไม่ต้อง Deploy และยังไม่ต้องเปิดแท็บ V3
4. ตรวจสอบ Properties ของแท็บ `STCR · ส่ง LINE (V3)` โดยไฟล์พร้อมใช้งานจะมี
   `STCR_LINE_TOKEN` และ `STCR_LINE_TO` จากระบบเดิมใส่ไว้แล้ว
5. ปิดแท็บ `DB`, `notify` และแท็บ V2 เดิมทั้งหมด
6. เปิดแท็บ V3 ทั้งสองแท็บ
7. กด `Deploy > Full` หนึ่งครั้ง
8. รอ 2 นาที ตรวจ Debug และตรวจหน้าเว็บว่าเตา 1-9 มีเวลาล่าสุดเปลี่ยน
9. ที่แท็บ `STCR · ส่ง LINE (V3)` กด Inject `ทดสอบส่ง LINE ทันที`
10. ที่แท็บรับข้อมูล V3 กด Inject `ทดสอบส่งแรงดัน AB/BC/CA ทันที`
    เพื่อตรวจว่าค่าไฟทั้งสามเฟสอ่านสำเร็จและส่งถึง LINE

## พฤติกรรมสำคัญ

- แต่ละ PLC อ่านเตาทีละเตา ไม่ยิงทุก Register พร้อมกัน
- เตา 1/4/7 เริ่มวินาที 2, เตา 2/5/8 เริ่มวินาที 22 และเตา 3/6/9
  เริ่มวินาที 42 ของรอบหนึ่งนาที
- แรงดันไฟฟ้าเริ่มอ่านวินาที 52 และอ่าน AB → BC → CA ตามลำดับ
- การเปลี่ยนสถานะจะแจ้งภายในประมาณ 1 นาที
- ตอนเปิด Flow ครั้งแรก ระบบจะจำสถานะตั้งต้นโดยไม่ส่งข้อความเริ่ม/หยุดทั้ง 9 เตาพร้อมกัน
- Alarm ที่ยังผิดปกติจะเตือนซ้ำทุก 1 ชั่วโมง และส่งข้อความเมื่อกลับสู่ปกติ

## ความปลอดภัย

ไฟล์พร้อมใช้งานมี Token LINE และรหัสผู้รับอยู่ใน Environment ของแท็บ
ห้ามนำไฟล์นี้หรือ Flow ที่ Export หลังติดตั้งขึ้น Git หรือส่งต่อในช่องทางสาธารณะ
